Game plan

How to work each question before any AWS knowledge comes into it.

Reading a question

  • Read the last line first (what's actually asked), then hunt for the constraint words: least overhead, cheapest, most secure, fewest code changes, highly available.
  • List every requirement in the stem. The right option satisfies all of them, not just the loudest one.
  • Two options both work? The tiebreaker is a specific feature (native rotation, free Gateway endpoint, managed retries), not general quality.
  • Select TWO/THREE: no partial credit. Pick the options that each stand alone as correct, not two halves of one idea.

Wrong-answer smells

  • Hardcoded/long-lived access keys, secrets in plaintext env vars or code.
  • "Write a custom script/cron/Lambda" when a managed feature already does it (lifecycle rules, DLQs, rotation, ECR lifecycle policies).
  • Legacy options: OAI, Classic Load Balancer, Launch Configurations, IMDSv1, Implicit OAuth grant.
  • Answers that solve a different problem: provisioned concurrency for DB connection floods, more capacity for a hot partition, larger instances for a bad health-check setting.
  • Pacing: answer and flag on the first pass, return later. No penalty for guessing, so never leave a blank.

DynamoDB capacity math (this shows up as a calculation question)

RCU = ceil(item KB ÷ 4) × reads/s for strongly consistent · ÷ 2 for eventually consistent · × 2 for transactional.

WCU = ceil(item KB ÷ 1) × writes/s · × 2 for transactional.

Example: 50 strongly consistent reads/s of 6 KB items → ceil(6/4)=2 → 100 RCU (eventual: 50). 20 writes/s of 2.5 KB → ceil(2.5)=3 → 60 WCU.

Module traps

Every module in study order, reduced to the traps you're most likely to see.

00Exam overview & IAM basicsFoundations
  • Survive a data-center outage = multi-AZ; survive a Region outage = multi-Region.
  • Policy logic: explicit Deny > Allow > implicit deny, across identity, resource, SCP and permissions boundary.
  • IAM roles beat access keys, every time. Hardcoded keys are always wrong.
  • Credential chain: code params → env vars → ~/.aws/credentials → config → container/instance role.
  • Handing a role to a service (Lambda, EC2, ECS) needs iam:PassRole.
  • Encoded "UnauthorizedOperation" message → aws sts decode-authorization-message.
  • MFA for CLI calls → aws sts get-session-token --serial-number … --token-code ….
  • Third-party cross-account role → trust policy + sts:ExternalId condition.
  • Permissions boundary caps one identity; SCP caps a whole account. Neither grants anything.
  • Which identity am I? aws sts get-caller-identity. Test permissions safely: IAM policy simulator or --dry-run.
01EC2 & computeD1
  • IMDSv2 (token, HttpTokens=required) over IMDSv1. Metadata lives at 169.254.169.254.
  • User data runs once, as root, at first boot.
  • T-instance slows down under sustained load = CPU credits exhausted → M/C family or Unlimited mode.
  • ASG with only EC2 health checks misses crashed apps → use ELB health checks.
  • Memory and disk usage need the CloudWatch agent. They aren't collected by default.
  • Client IP behind an ALB → X-Forwarded-For. Static IP, TCP/UDP → NLB. Path/host routing → ALB.
  • Security groups: stateful, allow-only. NACLs: stateless, allow + deny, evaluated in rule-number order.
  • Shell without opening port 22 → Session Manager.
  • Spot only for interruptible work (2-min notice). Per-socket licensing → Dedicated Hosts.
02S3 & storageD1
  • Strong read-after-write consistency for every operation. No "eventual consistency" caveat anymore.
  • Multipart: required >5 GB, recommended >100 MB. Add a lifecycle rule to abort incomplete uploads.
  • Hitting request limits → spread keys across more prefixes (3,500 writes / 5,500 reads per prefix).
  • Long-distance uploads → Transfer Acceleration. Parallel downloads → byte-range GETs.
  • Browser JS from another domain blocked → configure CORS on the bucket.
  • Enforce HTTPS → bucket policy Deny when aws:SecureTransport is false.
  • SSE-KMS throttling or high KMS cost → S3 Bucket Keys.
  • Presigned URLs carry the signer's permissions and expire. They can't grant more than the signer has.
  • Website endpoint is HTTP-only → CloudFront + ACM for HTTPS.
  • Replication needs versioning on both buckets. Existing objects need Batch Replication.
  • IA classes have a 30-day minimum and retrieval fees, so they're bad for short-lived or hot data. Storage: S3 = objects, EBS = one instance's disk, EFS = shared file system, instance store = scratch space.
03DynamoDBD1
  • Throttling with capacity to spare = hot partition → high-cardinality key or write sharding. More capacity isn't the fix.
  • FilterExpression doesn't save RCU: items are read first, then filtered. ProjectionExpression trims the response, not RCU.
  • Query needs a partition key and is efficient. Scan reads everything (parallel scan to speed it up).
  • Results come in 1 MB pages → pass LastEvaluatedKey back as ExclusiveStartKey.
  • Batch calls may return UnprocessedItems/Keys → retry those with backoff.
  • Optimistic locking = conditional write on a version attribute → ConditionalCheckFailedException on conflict.
  • Counters → UpdateItem with ADD (atomic). Multi-item all-or-nothing → transactions (2× cost).
  • TTL: epoch-seconds Number attribute. Deletes lazily (can take days), so expired items can still be read; filter them. Costs no WCU.
  • Streams keep 24 h. Change data capture = Streams + Lambda. Multi-Region active-active = Global Tables.
  • DAX: microsecond reads, write-through, API-compatible. It doesn't help strongly consistent reads or write-heavy loads.
  • On-demand for unpredictable/new traffic; provisioned + auto scaling for steady traffic (cheaper). Per-user rows → dynamodb:LeadingKeys.
04App patterns & LambdaD1
  • "Decouple" / "slow downstream shouldn't hurt caller" → put SQS (or SNS/EventBridge) between them.
  • Retries → exponential backoff + jitter. Duplicate side effects → idempotency key.
  • Sync invoke: no retry, the caller handles errors. Async: 2 automatic retries, then DLQ/on-failure destination. Poll sources follow their own rules.
  • SQS trigger: visibility timeout ≥ 6× function timeout. Partial batch failures → ReportBatchItemFailures.
  • Kinesis/DynamoDB Streams: a bad record blocks the shard → BisectBatchOnFunctionError, max retry attempts, max record age, on-failure destination.
  • More than 15 minutes of work → not Lambda (Fargate, Batch, Step Functions).
  • Slow CPU-bound code → raise memory. CPU and network scale with it.
  • VPC-attached Lambda loses internet → NAT Gateway or VPC endpoints. The execution role needs ENI permissions (AWSLambdaVPCAccessExecutionRole).
  • Runtime.ImportModuleError = missing dependency → bundle it or add a layer.
  • Versions are immutable, $LATEST is mutable, aliases point at versions and can split traffic between two.
  • Put SDK clients and DB connections outside the handler so warm invocations reuse them. /tmp persists only while the environment stays warm.
05API Gateway & AppSyncD1
  • Changes do nothing until you deploy the API to a stage.
  • Caching, usage plans/API keys, request validation, resource policies, WAF or a private endpoint → REST API. Cheapest/simplest Lambda proxy or JWT auth → HTTP API.
  • 502 = Lambda proxy response malformed (needs statusCode, headers, string body). 504 = integration took >29 s. 429 = throttled.
  • 403 "Missing Authentication Token" = wrong path/method, or an unsigned call to an IAM-auth API.
  • CORS with Lambda proxy → the Lambda must return Access-Control-Allow-Origin. The console toggle only sets up OPTIONS.
  • Environments → stage variables pointing at Lambda aliases. Grant lambda:InvokeFunction for each alias.
  • Cross-account IAM access → resource policy on the API + IAM policy on the caller + SigV4 signing.
  • Cache TTL defaults to 300 s. Clients can bypass it with Cache-Control: max-age=0 only if allowed execute-api:InvalidateCache.
  • Backend not built yet → Mock integration. Gradual rollout on a stage → canary release. Mapping templates (VTL) only on non-proxy integrations.
  • Real-time GraphQL, subscriptions, offline sync, multiple data sources → AppSync (several auth modes at once). Custom two-way protocol → WebSocket API ($connect, @connections).
06Messaging, streaming & analyticsD1
  • Standard SQS = at-least-once, best-effort order → consumers must be idempotent. FIFO = order per MessageGroupId + exactly-once (5-min dedup); queue name ends .fifo.
  • Same message processed twice → visibility timeout shorter than processing time → raise it or call ChangeMessageVisibility.
  • Empty receives and cost → long polling (WaitTimeSeconds up to 20).
  • DLQ: maxReceiveCount lives in the source queue's redrive policy. A FIFO queue needs a FIFO DLQ.
  • Payload too big → store it in S3 and send a pointer (Extended Client Library).
  • Fan-out: SNS → many SQS queues (the queue policy must allow SNS). Filter policies live on the subscription.
  • AWS service events, SaaS partner events, schedules, content routing → EventBridge.
  • Several consumers need the same data, or you need replay → Kinesis. A deleted SQS message is gone.
  • Kinesis hot shard → better partition key or more shards. Each consumer needs full speed → enhanced fan-out.
  • Firehose = managed delivery to S3/Redshift/OpenSearch, near real-time, no replay.
  • Athena = SQL on S3, billed per data scanned; cut cost with Parquet, compression, partitions. OpenSearch = log search and dashboards.
07Step FunctionsD1
  • "Must never double-process" or longer than 5 min → Standard. High-volume, short, idempotent → Express.
  • Map = loop over an array of unknown length. Parallel = fixed set of different branches.
  • Retry (IntervalSeconds, MaxAttempts, BackoffRate) first, then Catch → fallback state.
  • A later state lost its input → missing ResultPath (default overwrites). Use "ResultPath": "$.error" in Catch.
  • Human approval or external callback → .waitForTaskToken + SendTaskSuccess/Failure. A Wait state only waits a fixed time.
  • .sync waits for a job to finish (ECS task, CodeBuild, Glue).
  • Call AWS APIs directly from Task states (SDK integrations) instead of glue Lambdas.
  • State payload is 256 KB → pass S3 references for big data.
  • Central control, visibility, error handling → orchestration (Step Functions). Independent reactions → choreography (EventBridge).
08RDS, Aurora, ElastiCache, MemoryDBD1
  • Multi-AZ = synchronous standby for HA, not readable. Read replica = async, readable, scales reads, can be cross-Region.
  • Lambda → RDS "too many connections" → RDS Proxy. Not a max_connections bump, not provisioned concurrency.
  • Auto-rotate DB credentials → Secrets Manager. The rotation Lambda needs a network path to both the DB and Secrets Manager.
  • IAM database authentication → 15-minute token instead of a password (MySQL, PostgreSQL, Aurora).
  • Encrypt an existing unencrypted DB → snapshot → encrypted copy → restore. There's no switch to turn it on.
  • Aurora: reader endpoint for reads, Serverless v2 for spiky load, Global Database for cross-Region DR.
  • Redis OSS/Valkey: replication, persistence, sorted sets, pub/sub. Memcached: multithreaded and simple, no persistence.
  • ElastiCache is a cache. A durable Redis-compatible database of record → MemoryDB.
  • Joins and multi-table SQL → relational. Huge scale with known access patterns → DynamoDB.
09Caching & performanceD1D4
  • Pseudocode test: get cache → if null → query DB → set cache = lazy loading. Write to DB + cache together = write-through.
  • Read-through = the cache layer loads on a miss for you (DAX). Lazy loading = your code does it.
  • TTL is the staleness safety net on top of any strategy. "At most N seconds stale" is a TTL question.
  • Users see someone else's cached data → the cache key doesn't include identity → don't cache it (Cache-Control: private) or add the header to the key.
  • Content varies by language → add Accept-Language to the cache key. Keep Authorization out of shared caches.
  • Low CPU but high latency → I/O-bound (DB, network), not a memory problem.
  • Lambda cost = GB-seconds; the cheapest memory setting is found by measuring (Power Tuning), rarely the minimum.
  • Stateless fleet needs sessions → ElastiCache or DynamoDB, not sticky sessions.
10CI/CD & developer toolingD3
  • Files at the root: buildspec.yml (CodeBuild), appspec.yml (CodeDeploy), .ebextensions/*.config (Beanstalk).
  • Build secrets → env: parameter-store / secrets-manager in buildspec, never plaintext variables.
  • EC2 hook order: ApplicationStop → BeforeInstall → AfterInstall → ApplicationStart → ValidateService. Lambda/ECS hooks: BeforeAllowTraffic / AfterAllowTraffic.
  • EC2/on-prem deploys need the CodeDeploy agent and an instance profile that can read the revision from S3.
  • Auto rollback on failure or a CloudWatch alarm. Rollback = redeploy the last good revision (new deployment ID).
  • Lambda/ECS configs: Canary10Percent5Minutes, Linear10PercentEvery1Minute, AllAtOnce. EC2: AllAtOnce, HalfAtATime, OneAtATime.
  • Blue/green = fastest rollback, runs 2 environments. In-place/rolling = cheapest, slow rollback, mixed versions mid-deploy.
  • Human sign-off → CodePipeline manual approval + SNS.
  • Config/feature-flag rollout with validators and alarm rollback, no code deploy → AppConfig (Parameter Store can't stage rollouts).
  • Private packages + cached npm/PyPI/Maven → CodeArtifact (aws codeartifact login). CodeBuild reaching private resources → run it in the VPC.
  • CodeStar is a legacy project wrapper around the Code* services, not a deployment engine.
11Elastic Beanstalk, Amplify, CopilotD3
  • Background jobs from SQS, no public traffic → worker tier (cron.yaml for periodic tasks).
  • Full capacity during deploy → rolling with additional batch. Safest & fastest rollback → immutable or blue/green.
  • Blue/green = a second environment + Swap environment URLs (CNAME). It isn't one of the in-place policies.
  • Don't create the production RDS instance inside the environment; it dies with the environment. Create it separately and pass the endpoint in.
  • .ebextensions can hold CloudFormation Resources. container_commands run after unzip (leader_only for once).
  • Deploying often → application version lifecycle policy (1,000-version quota).
  • "Amplify branches" = Git branch per environment + PR previews. "Copilot environments" = named dev/test/prod container targets.
  • Lambda aliases, image tags, Amplify branches and Copilot environments all serve as approved-version pointers.
12Containers: ECS, ECR, Fargate, EKSD3
  • Execution role = pull image, write logs, fetch secrets (task won't start). Task role = your app's AWS calls (AccessDenied at runtime).
  • Least ops for containers → Fargate (awsvpc mode, one ENI per task). Cost at scale with host control → EC2 launch type.
  • Kubernetes, Helm, portability → EKS (pod permissions via IRSA / EKS Pod Identity). EKS can run on Fargate too.
  • Shell into a running container → ECS Exec.
  • ECR login: aws ecr get-login-password | docker login --username AWS --password-stdin …
  • Old images → ECR lifecycle policy. Vulnerabilities → ECR scanning (enhanced = Inspector). Pin deploys to an immutable tag or digest.
  • Placement strategies (binpack, spread, random) and constraints (distinctInstance, memberOf) apply only to the EC2 launch type.
  • ECS blue/green → CodeDeploy. Safer rolling deploys → deployment circuit breaker with rollback.
13IaC: CloudFormation, SAM, CDKD3
  • SAM and CDK both end up as CloudFormation stacks: change sets, rollback, drift, DeletionPolicy all apply.
  • Secrets in templates → dynamic references {{resolve:secretsmanager:…}} / {{resolve:ssm:…}}.
  • Local Lambda code in a template → aws cloudformation package / sam package uploads it to S3 first.
  • Change sets preview. Drift detection reports only and never fixes anything.
  • You can't delete/change an Export that another stack imports.
  • Stack delete fails on a non-empty S3 bucket. Keep data → DeletionPolicy: Retain or Snapshot.
  • No native resource type → Lambda-backed custom resource. Wait for EC2 bootstrap → CreationPolicy + cfn-signal.
  • SAM: Transform: AWS::Serverless-2016-10-31, sam build, sam local invoke/start-api, sam deploy --guided. New stage → parameter overrides / config env.
  • SAM AutoPublishAlias + DeploymentPreference → CodeDeploy canary/linear with PreTraffic/PostTraffic hooks.
  • CDK: cdk bootstrap once per account+Region, cdk synth → template, cdk diff, cdk deploy. Constructs: L1 (Cfn*), L2, L3 patterns.
14Security deep diveD2
  • User pool = sign-in, JWTs (ID for identity claims, access for API scopes, refresh). Identity pool = temporary AWS credentials, guests allowed.
  • Customize sign-up/tokens → Cognito Lambda triggers (pre sign-up, pre token generation, post confirmation, migrate user).
  • Validate a JWT: signature against the pool's JWKS, then exp, iss, aud/client_id, token_use. SPA/mobile → Authorization Code + PKCE.
  • Data > 4 KB → envelope encryption (GenerateDataKey, encrypt locally, store encrypted key alongside). KMS throttling → data key caching / Bucket Keys.
  • A KMS key needs its key policy to allow access; IAM alone isn't enough. Cross-account → key policy in owner + IAM policy in caller.
  • Customer managed key when you need your own key policy, per-key audit or the ability to disable. Rotation keeps the same key ID/ARN.
  • Rotating credentials → Secrets Manager. Static or free config → Parameter Store (SecureString uses KMS).
  • Lambda env vars are encrypted at rest by default. Hiding them from console viewers → encryption helpers + customer managed key + decrypt in code.
  • CloudFront cert → ACM in us-east-1. Free ACM public certs can't go on EC2 → terminate TLS on ALB/CloudFront/API Gateway.
  • WAF for SQLi/XSS/rate limits on CloudFront, ALB, API Gateway (REST), AppSync, Cognito. Not directly on EC2 or S3.
  • Never log secrets or PII → mask them (CloudWatch Logs data protection policies).
15Networking for developersD1
  • Internet Gateway = two-way, public subnet. NAT Gateway = outbound-only for private subnets.
  • Gateway endpoint = S3 and DynamoDB only, free. Everything else = Interface endpoint (paid). "Cut NAT cost" for S3 traffic → Gateway endpoint.
  • Lambda needs VPC attachment only to reach private resources (RDS, ElastiCache). It can call S3/DynamoDB/SNS without one.
  • Zone apex → Alias record (CNAME can't sit at the apex; Alias queries to AWS targets are free).
  • Routing policies: weighted (A/B split), latency, failover + health check (DR), geolocation, multivalue.
  • OAC locks S3 to one CloudFront distribution. Restricting viewers needs signed URLs/cookies too.
  • Stale CloudFront content → versioned file names (best) or invalidation.
  • Simple header/redirect logic → CloudFront Functions. Network calls or origin events → Lambda@Edge.
  • Debug accepted/rejected traffic → VPC Flow Logs.
16Monitoring, logging & observabilityD4
  • X-Ray annotations are indexed (filter expressions). Metadata isn't indexed. Anything you'll search by goes in an annotation.
  • X-Ray setup: daemon on UDP 2000 (sidecar on ECS), active tracing toggle on Lambda and API Gateway, role needs xray:PutTraceSegments.
  • Custom metrics: PutMetricData or EMF (structured JSON logs, no API calls, high cardinality). High resolution = 1 s.
  • Metric filters only see new log events. Log retention is "never expire" by default → set it.
  • Real-time log processing → subscription filter (Lambda/Kinesis/Firehose). Ad-hoc questions → Logs Insights (fields, filter, stats, sort).
  • CloudTrail logs management events by default (90-day history). Data events (S3 objects, Lambda invokes) must be turned on.
  • Alert on an event (deploy finished, pipeline failed) → EventBridge + SNS. Alert on a number crossing a line → CloudWatch alarm + SNS.
  • Deployment failed → CodeBuild logs, CodeDeploy lifecycle events, CloudFormation stack events. The app logs may be empty because the app never started.
  • CodeGuru Reviewer = static code review. CodeGuru Profiler = runtime hotspots.
17Well-Architected & strategyReview
  • Six pillars: Operational Excellence (automate, IaC, small reversible changes), Security (least privilege, encryption, traceability), Reliability (multi-AZ, retries, auto-recovery), Performance Efficiency (right service, caching, serverless), Cost Optimization (pay-per-use, right-size, lifecycle), Sustainability (managed services, less idle capacity).
  • Typical trade-offs: Multi-AZ vs cost, KMS customer managed key vs simplicity, provisioned concurrency vs cost.
  • Integrative questions combine two modules, e.g. Lambda concurrency + SQS DLQ, or IAM role + Secrets Manager. Solve each half with its own module's rule.
  • Managed service beats self-built almost every time the stem says "least overhead".

Errors & exceptions

What the error means and the fix the exam expects.

HTTP status codes

CodeMeaning → fix
400Bad input (ValidationException) → fix the request
401Missing/invalid token at an authorizer → send a valid JWT
403Denied by IAM, resource policy, WAF or authorizer. "Missing Authentication Token" = wrong path/method

429Throttled → backoff + jitter, usage plan/quota increase
500Unhandled exception in your code
